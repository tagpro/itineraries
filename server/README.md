# Itineraries API

A small Go service that lets the checklists on the itinerary pages sync
between phones. It runs as a Cloudflare Worker at
`https://travel.jaspreet.casa/api/v1`, stores its state in Cloudflare D1
(SQLite), and deploys from GitHub Actions on every push to `main` that
touches `server/`.

It is universal: one deployment serves every itinerary, now and in future.
Each itinerary is a **trip**; each trip holds any number of **lists**; each
list is a map of keyed **entries**. The server does not know or care what a
key means — the page does.

## How syncing works

Every entry carries the time its author last changed it:

```json
{ "v": true, "t": 1757656740000 }              // a built-in tick
{ "v": {"t": "Buy honey"}, "t": 1757656800000 } // an item someone added
{ "v": {"t": "Buy honey"}, "t": 1757657000000, "d": true } // …then deleted
```

When two copies disagree, the later `t` wins. That single rule — a map of
last-writer-wins registers, the simplest CRDT there is — is applied in three
places and gives the same answer in all of them: `domain.Merge` in Go, the
`ON CONFLICT` clause in `queries.sql`, and the page's own JavaScript. So a
phone can go offline for a day, come back, `PATCH` its entire local state,
and receive the merged truth in one round trip. Nothing is ever rolled back
by a stale write, and sending the same state twice is harmless.

Deletes are tombstones (`"d": true`) so that a delete can lose to a later
re-add under the same rule. Stamps come from the client's clock; a stamp
more than five minutes in the future is rejected, because a phone with a
wrong clock would otherwise win every merge for as long as it stayed wrong.

## API

All routes are under `/api/v1`. Two credentials, both sent as
`Authorization: Bearer …`:

- the **admin key** (`ADMIN_KEY`, a Worker secret) creates trips and rotates
  their tokens;
- a **trip token**, minted at creation and shown once, reads and writes that
  one trip. There are no accounts. Whoever holds the token is on the trip.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `GET` | `/healthz` | none | `{ok, version}` |
| `POST` | `/trips` | admin | Create `{id, name}` → `{id, name, created_at, token}` |
| `GET` | `/trips` | admin | List trips (no tokens) |
| `POST` | `/trips/{trip}/token` | admin | Rotate → `{token}`; the old one stops working |
| `GET` | `/trips/{trip}` | trip | Whole trip: `{id, name, created_at, lists: {list: {key: entry}}}` |
| `PATCH` | `/trips/{trip}` | trip | Merge `{lists: {…}}`, respond with the whole trip |
| `GET` | `/trips/{trip}/lists/{list}` | trip | One list: `{id, entries}` |
| `PATCH` | `/trips/{trip}/lists/{list}` | trip | Merge `{entries: {…}}`, respond with the list |

A wrong token and a non-existent trip both answer `401`, so nobody can
enumerate trip ids. Trip and list ids are slugs (`[a-z0-9-]`, ≤ 64); keys
are `[A-Za-z0-9_.:-]` (≤ 64); a value is at most 4 KB of JSON; a request
carries at most 2000 entries. Errors are always `{"error": "…"}`.

```sh
# Create a trip (once per itinerary)
curl -X POST https://travel.jaspreet.casa/api/v1/trips \
  -H "Authorization: Bearer $ADMIN_KEY" \
  -d '{"id":"tassie-campervan-2026","name":"Tasmania, Sep 2026"}'

# Sync from a page: send everything local, get everything merged back
curl -X PATCH https://travel.jaspreet.casa/api/v1/trips/tassie-campervan-2026 \
  -H "Authorization: Bearer $TRIP_TOKEN" \
  -d '{"lists":{"before":{"b1":{"v":true,"t":1757656740000}}}}'
```

## Layout

```
server/
  main.go               Cloudflare Workers entry (build tag js && wasm)
  main_dev.go           net/http entry with an in-memory store (everything else)
  internal/
    domain/             types, the merge rule, validation — no dependencies
    auth/               tokens: generation, hashing, constant-time checks
    store/              Store interface; SQL (D1 / SQLite) and Memory implementations
      queries.sql       every statement the SQL store runs, compiled by sqlc
      queries/          generated by sqlc — do not edit
    api/                HTTP: routes, handlers, auth middleware, CORS, JSON
  migrations/           D1 migrations; also the schema sqlc compiles against
  sqlc.yaml             sqlc configuration
  wrangler.jsonc        Worker, route, D1 binding, vars
```

`domain` is pure and `store.Memory` is complete, so the handlers are tested
with `httptest` and no database. `store.SQL` is tested against a real
SQLite file built from the actual migration, and one test asserts that its
`ON CONFLICT` merge produces exactly what `domain.Merge` produces, in either
order. sqlc keeps the Go and the SQL in step: `make sqlc-check` fails CI if
`queries.sql` or a migration changes without regenerating.

On Cloudflare the Go program is compiled to WebAssembly and driven by a
small JS shim from [`workers-go`](https://github.com/syumai/workers-go).
The shim instantiates the program per request with the request's bindings
attached, which is why `main.go` can open D1 and read `ADMIN_KEY` directly.
D1 speaks `database/sql` through the same package; it has no transactions,
which is fine because every statement here is atomic on its own.

## Working on it

```sh
make test          # go vet + go test, natively, no wrangler needed
make run           # the API on http://127.0.0.1:8787 with an in-memory store
make sqlc          # regenerate internal/store/queries after editing SQL
make wasm          # compile the Worker into ./build
make size          # …and check it fits the free plan (3 MB gzipped)
npm run dev        # the real Worker on a local D1, via wrangler
```

For `npm run dev`, put the admin key in an untracked `.dev.vars`:

```
ADMIN_KEY=anything-you-like-locally
```

## One-time setup

Everything after this is automatic, but these steps need your Cloudflare
account and happen once.

1. **Create the database.** From `server/`, with `npx wrangler login`
   done:

   ```sh
   npx wrangler d1 create itineraries
   ```

   Paste the `database_id` it prints into `wrangler.jsonc` and commit.

2. **Add three GitHub Actions secrets** to the repository:

   | Secret | What |
   |---|---|
   | `CLOUDFLARE_ACCOUNT_ID` | From the Workers overview page in the dashboard |
   | `CLOUDFLARE_API_TOKEN` | An API token with **Workers Scripts: Edit**, **D1: Edit**, **Workers Routes: Edit** on the `jaspreet.casa` zone, and **Account Settings: Read** |
   | `API_ADMIN_KEY` | Any long random string, e.g. `openssl rand -base64 32` |

   The workflow pushes `API_ADMIN_KEY` into the Worker as `ADMIN_KEY` after
   each deploy, so rotating it is a matter of changing the GitHub secret.

3. **Point DNS at GitHub Pages, proxied.** In the `jaspreet.casa` zone:

   | Type | Name | Content | Proxy |
   |---|---|---|---|
   | `CNAME` | `travel` | `tagpro.github.io` | **Proxied (orange cloud)** |
   | `TXT` | `_github-pages-challenge-tagpro` | the code GitHub shows under *Settings → Pages → Verified domains* | n/a |

   The record **must be proxied**: Worker routes only see traffic that
   passes through Cloudflare. Set SSL/TLS to **Full** (not Flexible, which
   loops with GitHub Pages). Then set the repository's custom domain to
   `travel.jaspreet.casa` under *Settings → Pages* — which rewrites the root
   `CNAME` file — and tick *Enforce HTTPS* once GitHub has issued the
   certificate. A repository has one custom domain, so this replaces
   `travel.jaspreet.info`; a Cloudflare redirect rule on the old zone keeps
   old links working.

4. **Push to `main`.** The `API` workflow applies migrations, builds the
   Worker, deploys it, and sets the secret. Until the DNS record exists the
   Worker is also reachable at its `*.workers.dev` URL.

5. **Create the first trip** with the `curl` above, and hand the token to
   the page.
